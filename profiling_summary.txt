Key Findings

1. TRANSACT CPU: 87% in syscalls (pread/pwrite/mmap) = SQLite I/O dominates
   - 43.5% in sqlite3BtreeIndexMoveto (B-tree lookups for INSERT/REPLACE)
   - Go-side code is negligible; transact is I/O-bound

2. QUERY CPU: 92% in sqlite3VdbeExec (SQLite VM execution)
   - 84% in balance_nonroot -- heavy B-tree rebalancing during scan
   - Query compilation (parse+algebrize+translate) is <1% of query time

3. TRANSACT MEMORY: 77% in transact.func1 (the closure passed to withWriteConn)
   - encodeValue/encodeInt64 account for ~6MB (5.4%)
   - fmt.Sprintf for TempID generation is 4% -- benchTransactN overhead
   - ~424 allocs/op for 100-datom tx = ~4.2 allocs per datom

4. VALUE ENCODING: sub-nanosecond for int64/float64 encode/decode (zero alloc)
   - encodeValue adds ~10ns overhead for type dispatch + make([]byte,8)
   - String encoding is dominated by []byte conversion (1 alloc)

5. QUERY COMPILATION: ~2.5us simple, ~4.6us join (67-116 allocs)
   - EDN parsing is ~2.7us for a full query string (68 allocs)
   - Parse+algebrize+translate is <0.5% of full query execution time
